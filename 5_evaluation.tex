\section{Evaluation}
\label{sec:experiments}

We ask a narrower question than a completed benchmark paper answers: does the active
admissibility-gated rule improve on simpler enrollment rules on the development roster? We report
that result here. We leave the external test roster and several tokenizer ablations unevaluated, and
we state them as pending measurements rather than filling the space with fabricated cells.

The completed run trains for 30,000 steps. The subject-disjoint Phase-A selection metric peaks at
step 4,000 (label--stream-macro balanced accuracy $0.3028$), so \texttt{best.pt} rather than the
last checkpoint builds the reported bank. Dense development-only comparisons also favor this
checkpoint; the test roster is not involved in that choice.

\subsection{Evaluation Protocol}
\label{sec:eval_protocol}

An evaluation dataset supplies its own candidate inventory; this is a HALO protocol choice, not a
claim established by the generalized zero-shot-learning benchmark. Following that benchmark, we
separately report whether a candidate was seen or unseen during training~\cite{zslgbu}. Macro-F1 is
primary because activity frequencies are imbalanced.

For enrollment, support and query executions are disjoint. The development evaluation uses
cross-subject, same-configuration cohorts for MotionSense, RealWorld, and Shoaib. At each
$k\in\{1,2,4,8\}$, we retain the same queries and candidate inventory and nest the support prefixes.
A verified recording execution, not an adjacent window, counts as one example. We also run support
removal, cyclic support-label shuffling, an all-one admissibility control, prototypes, and ridge
heads on the identical features and support split.

The test roster was fixed before the present gate evaluation: InclusiveHAR, USC-HAD, TNDA-HAR,
UT-Complex, MoniPar, SPAR, and Upper Limb Use. TNDA-HAR has no usable subject-disjoint enrollment
cohort and contributes only to a future zero-support cell. SPAR's repetitions occur within one bout
and do not establish across-session enrollment. MoniPar is the held-out source that can support
across-week enrollment. We do not consume any of these test datasets in the present revision.

\subsection{Development Result: the Gate Does Not Beat Simpler Controls}
\label{sec:label_efficiency}

development datasets. ``Ungated'' uses the identical prediction path with admissibility fixed to
one. Prototype and ridge operate on the same frozen representation and enrolled executions.

The support interventions show that the gated rule uses enrollment: removing or shuffling support
substantially reduces macro-F1. That fact is insufficient for a performance claim. Ungated
retrieval is 11.3--14.0 points better at $k=1$ through 4, and prototypes are 16.9--32.3 points
better across the enrollment curve. Performance also falls from $k=4$ to 8 for the gated rule while
prototype and ridge improve.

The telemetry identifies a concrete mechanism. Across every reported development cell, gate values
range from $0.245$ to $0.733$, above the configured veto threshold $0.15$; consequently the hard
veto removes no row. The gate only reweights already selected evidence and cannot demonstrate the
paper's intended admissibility behavior. We therefore reject the hypothesis that the current gate
improves few-example recognition. The seven-dataset test evaluation remains sealed rather than
being spent on a method that fails its development controls.

\subsection{Required Measurements Before a Performance Claim}
\label{sec:pending_measurements}

The following experiments are part of the protocol but do not yet have provenance-complete
artifacts:

\begin{itemize}
  \item held-out concept, dataset, and body-region studies for the gate, including gate-collapse,
        provenance-capture, and latent-to-measurement guards;
  \item cross-configuration enrollment on simultaneous training streams, reported separately from
        the external test result;
  \item native-grid versus common-rate, sensor-folded versus channel-level, descriptor-off,
        acquisition-bias-off, observability-off, and signed-low-frequency ablations;
  \item all-pairs activity-text similarity versus sensor-centroid similarity, replacing any
        hand-selected quantitative geometry claim;
  \item data-matched and released-checkpoint baselines, including the published short fine-tuning
        baseline required by the wearable-foundation-model literature; and
  \item only after development criteria are met, one evaluation of the seven-dataset sealed test
        roster with confidence intervals and seen/unseen candidate breakdowns.
\end{itemize}

No on-device latency, Core~ML, iOS, or unknown-class result is claimed because the corresponding
implementation and measurement artifacts do not exist in the repository.
